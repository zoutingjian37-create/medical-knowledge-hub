# 医学文献讲解

把论文讲清楚，而不是把摘要换一种说法。表达可以吸收优秀医学科普文章的通俗节奏，但不得逐句模仿某个公众号、复制固定口头禅或保留广告话术。

## 输入边界

- 优先使用论文全文；只有摘要时明确标记“摘要级证据”。
- 公众号二次讲解只能作为表达参考，不能替代原始论文核验。
- 来源缺失或无法判断证据层级时停止推断，明确写出缺口。

## 讲解方法

1. 先说明这篇研究解决什么真实临床或科研难题，以及为什么值得看。
2. 用普通研究者能理解的语言交代人群、数据、暴露/干预、结局、时间和比较关系。
3. 把统计方法翻译成“它在回答什么问题、为什么适合、前提是什么”，必要时用对比或小例子解释。
4. 以定性结论为主；只保留会改变判断的关键数字，不堆结果表。
5. 分开说明研究问题创新、数据/设计创新、统计方法原创、方法应用创新和仅仅使用高级方法。复杂不等于创新。
6. 给出可迁移的科研设计启发，同时明确偏倚、外推限制和因果边界。
7. 删除课程、报名、二维码、咨询、社群和商业推广内容。

## 表达要求

- 成文前读取 [语言动作](references/language-style.md)，按材料类型选择表达路线；不要机械调用全部动作。
- 采用“痛点或问题 → 研究怎么做 → 方法白话解释 → 发现 → 价值与边界”的递进节奏。
- 短段落、明确小标题；术语第一次出现时给出直白解释。
- 可以使用克制的设问、对比和例子帮助理解，不制造点击诱饵，不夸大可发表性。
- 不得生成原文没有支持的结论、P 值、效应量、机制或创新声明。

## 输出

严格遵循 [输出契约](references/output-contract.md)。输出必须是一篇可阅读的“论文讲解”，按“值得看什么 → 怎么做 → 为什么这样分析 → 结果意味着什么 → 能否迁移”的节奏组织，而不是把研究拆成互不相连的资料卡栏目。

固定章节依次为“为什么值得看、研究问题、研究怎么做、统计方法为什么这样选、主要发现、这篇研究的新意、对科研设计的启发、局限与证据边界、原论文图与方法图、来源”。

每篇必须保留一张 Mermaid 方法图；有可公开核验的原论文图时，额外写图号、图意和来源链接。不得复制受限 PDF 图片、把截图当证据，或凭空生成结果图。风格方法和反例见 [讲解方法审计](references/style-methodology.md)，语言动作见 [语言蒸馏规则](references/language-style.md)。只生成预览，等待用户确认后再写入 Obsidian。
