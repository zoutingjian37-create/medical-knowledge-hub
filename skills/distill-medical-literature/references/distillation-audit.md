# 仓颉蒸馏审计

本 Skill 使用仓颉方法的 RIA-TV++ 路线，从 10 篇公众号文章抽象可复用的“医学文献解释系统”。只蒸馏结构、判断规则和边界，不复制原文表达。

## Stage 0：整体概览

样本覆盖前瞻性队列、随机对照试验、SMART 自适应试验、两阶段真实世界比较、多中心预测模型、因果森林、纵向重复测量和顶刊方法趋势。

共同叙事骨架是：

`临床痛点 → 研究问题 → PICO/PECO → 数据与变量 → 方法为何必要 → 主要发现 → 临床价值与方法学价值 → 局限 → 可迁移方向`

稳定优点：临床问题导向、方法与数据难题绑定、善于把复杂统计翻译成研究设计语言、结尾能提取迁移价值。

稳定噪声：顶部和中部咨询广告、二维码、课程导流、影响因子崇拜、“可直接复刻”式承诺、重复总结、往期推荐和界面文字。

## Stage 1：五路提取候选

### 结构提取

1. 问题先行，而不是从论文目录或统计名词开始。
2. 用 PICO/PECO 固定研究对象、暴露/干预、对照与结局。
3. 数据与变量按分析用途分组。
4. 方法解释围绕它解决的偏倚、相关结构或推断问题。
5. 结果、价值、局限和迁移分开表达。

### 机制提取

1. 方法选择由数据结构驱动，而非由“高级感”驱动。
2. 创新来自新问题、新设计、新数据、新机制或新验证，不来自方法名本身。
3. 可迁移性取决于时间顺序、变量可得性、事件数和验证条件。

### 决策提取

1. 先判断来源层级，再决定能否使用因果或确定性措辞。
2. 只保留会改变判断的数字。
3. 单篇证据只能生成知识卡和灵感，不能直接升级为研究范式或可立项方案。

### 反例提取

1. 中介比例不能直接翻译成干预可减少同等比例风险。
2. 训练集 AUC 高不能证明机器学习优于传统回归。
3. 安全终点不显著不能证明两方案安全等效。
4. 非显著交互不能证明亚组效应完全一致。
5. 复杂方法、显著 P 值、顶刊和高影响因子都不是创新的充分条件。

### 表达提取

保留“临床问题—方法理由—结论边界”的解释节奏；去除夸张标题、营销承诺、绝对化判断和来源独有措辞。

## Stage 1.5：三重验证

### V1 跨样本验证

| 原子规则 | 支持样本 | 结论 |
|---|---:|---|
| 临床问题先行 | 1、3、4、7、9、10 | 跨队列、RCT、预测研究稳定存在 |
| PICO/PECO 与变量地图 | 1、3、4、7、9 | 能恢复研究设计，不依赖疾病类型 |
| 方法—问题映射 | 1–10 | 是最稳定的解释机制 |
| 临床价值与方法学价值分离 | 1、2、3、4、7、9、10 | 能避免把“有意义”混成“有创新” |
| 局限与迁移约束 | 1、2、3、4、7、9 | 决定知识能否安全复用 |
| 广告边界 | 1–10 | 固定出现，可规则化清洗 |

### V2 预测力验证

面对一篇未见过的医学文献讲解，上述规则能预测合格输出应包含哪些部分，也能提前识别常见失败：术语堆砌、数值抄录、因果过度、机器学习崇拜、广告污染和随机拼接选题。因此不是事后摘要标签。

### V3 独特性验证

该体系不是通用“总结文章”：它要求恢复研究设计、解释方法与数据难题的对应关系、区分三类统计创新、显式标注证据层级，并以迁移约束控制选题生成。这些约束共同构成可操作差异。

## Stage 2：RIA++ 原子单元

### A. 临床问题压缩器

- R：医学材料常从背景或标题开始，研究问题不够清楚。
- I：先压缩成“人群—问题—比较—结局”。
- A1：从导语、纳排标准和主要结局恢复一句话问题。
- A2：预测研究改写为“谁、何时、预测什么、用于什么决策”。
- E：公众号材料可能省略对照或时间顺序。
- B：缺失即标记，不猜测。

### B. 研究骨架恢复器

- R：长文容易把变量、方法和结果混在一起。
- I：PICO/PECO 加变量用途分类能恢复最小研究模型。
- A1：优先提取 P、I/E、C、O。
- A2：补充混杂、机制、效应修饰、重复测量和验证结构。
- E：诊断、预测和方法学论文不必强行套 PICO。
- B：采用与研究类型匹配的骨架。

### C. 方法—问题翻译器

- R：列方法名不能解释为何使用。
- I：方法价值来自它解决的具体数据或推断难题。
- A1：逐项写“难题→方法→新增信息→前提”。
- A2：多个方法按主分析、稳健性、机制和验证分层。
- E：公众号可能把常规使用包装为创新。
- B：复杂不等于创新。

### D. 结论压缩与边界门

- R：数值堆砌会淹没真正结论。
- I：方向、稳定性、适用人群和不确定性比全部数字更可复用。
- A1：默认去掉效应值、区间和 P 值。
- A2：只保留改变临床判断、阈值或可行性的数字。
- E：不显著与等效、相关与因果容易混淆。
- B：显式添加证据边界。

### E. 创新雷达

- R：高阶方法常被误判为创新。
- I：创新必须说明相对常规方案新增了什么可检验能力。
- A1：扫描八个创新维度。
- A2：统计方法只归入方法学原创、方法应用创新或高级方法使用。
- E：单纯使用机器学习、LASSO、SHAP、GEE 或倾向评分不是创新。
- B：无创新时允许明确写“未识别到”。

### F. 迁移与选题约束器

- R：随机替换疾病、指标和方法会制造伪选题。
- I：迁移必须保留原设计的识别逻辑和数据条件。
- A1：列出可替换与不可替换组件。
- A2：生成问题、数据、变量、分析、创新、风险和核查任务完整候选。
- E：来源讲解不能证明研究空白仍存在。
- B：只标记灵感候选或待核查。

### G. 广告与界面清洗器

- R：公众号正文混有稳定的推广与界面噪声。
- I：这些片段可由语义和位置双重识别。
- A1：删除咨询、课程、二维码、关注、往期、点赞留言。
- A2：重复导语和夸张承诺也删除。
- E：不要误删真正的研究资助、利益冲突或干预描述。
- B：只删除与论文知识无关的推广。

## Stage 3–4：关系与压力测试

原子单元依赖关系为：来源分级 → 广告清洗 → 临床问题 → 研究骨架 → 方法—问题映射 → 结果边界 → 创新雷达 → 迁移选题 → Wiki 预览。

已用以下反例压力测试：纯统计教程、只有摘要的二次讲解、无对照预测研究、训练集性能很高但验证下降、观察性中介分析、安全差异不显著、单中心小样本和顶刊方法清单。每种情形都有降级路径，不要求强行填满所有章节。

## Stage 5：交付原则

1. Skill 只保存规则、输出契约和来源清单，不保存 10 篇正文。
2. 新材料的永久来源只写公开链接。
3. Codex 生成预览，Obsidian 归档必须等待用户确认。
4. 如需“可直接立项”，必须另行完成原论文、研究空白、数据字典、事件数和可行性核查。
