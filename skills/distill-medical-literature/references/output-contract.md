# 输出契约

输出一份 Markdown 预览。Frontmatter 使用以下字段：

```yaml
---
source_url: "https://公开来源地址"
source_platform: wechat | journal | pubmed | europe_pmc | website | other
source_account: "作者、公众号或期刊"
source_title: "来源标题"
published_at: "YYYY-MM-DD 或未识别"
evidence_level: public_account_summary | abstract_verified | full_text_verified
status: preview
wiki_updates: []
---
```

正文使用 4–6 个自然小节。小标题必须来自论文真正要解决的矛盾、作者采取的动作或结果带来的变化，不使用固定字段名排队。全文至少覆盖研究问题、研究设计与方法、主要发现、价值与迁移以及来源；这些内容可以合并在同一条叙事线上。

```markdown
# 一句话结论式标题

## 为什么原来的方法总会漏掉一部分人？
用 1–2 句提出研究或临床决策困境，顺势交代研究问题。不能用夸张标题代替问题。

## 作者加了哪一步？
沿着作者的实际操作说明数据、研究设计和方法理由；必要时把“统计方法为什么这样选”融入其中，不另列术语表。

## 效果到底怎么样？
把主要发现和真正支撑结论的图片放在一起。保留会改变判断的数字，不复述结果表。

## 这个思路可以怎么用？
把文章实际贡献自然写进讲解，再说明可迁移的研究结构和数据条件。创新类型只在后台分类，正文不写“属于某类创新”或“不硬凑某类创新”。

上面只是自然标题示例，不是固定章节。每节开头要接住上一节留下的问题；方法、结果和图片沿同一条线推进。成文后去掉小标题后仍能连续读通。

全文可核验且图像许可允许复用时，选择 1–3 张原论文图中的关键结果图实际嵌入正文。图文讲解直接从图中的对象、动作或差异开始，不要写“图 X 的重点是”或“最后回到整套流程看一遍”；随后把可见特征翻译成研究含义，并标注论文来源与许可。受限许可或只有摘要时只写图号、图意和公开来源链接。原论文已有清楚的方法图时不重复画 Mermaid；只有缺少可复用方法图时才按材料补画。

## 来源

状态：等待用户确认
```

规则：

- `source_url` 必须是永久公开来源，不能是临时缓存路径。
- 只有对照摘要或全文后，才能使用 `abstract_verified` 或 `full_text_verified`。
- “主要发现”以定性结果为主，只保留会改变判断的数字。
- 文章贡献由文章内容决定类型；统计方法、暴露因素或指标创新只在文章有支持时写入。分类供后台结构化记录使用，正文直接讲清作者改变了什么以及带来了什么结果。
- “对科研设计的启发”中的选题只能标记为“灵感候选”或“待核查”，不得声称可直接立项。
- `wiki_updates` 只列相对 Vault 根目录的 Markdown 路径；默认只生成建议。
- 不保存原文，不把广告、课程、二维码或咨询信息写入任何章节。
- 不能凭空画结果图、机制图或流程图；Mermaid 只能表达材料明确支持的研究设计与分析关系。
- 成文后执行“语言自检”：开场在 3 句内进入问题；每节最多 1–2 个有效设问；每段只完成一个认知动作；类比必须回到正式术语和边界。
- 开放许可全文优先嵌入直接支撑主要发现的结果图，不得用 Mermaid 流程图代替已有的关键结果图。
- 图片在正文推进到对应方法或结果时出现。直接写图中对象发生了什么，再解释它支持什么；只有容易误读时才补一句限制。删除装饰图、录用图、二维码和无信息截图。
- 不复制来源的固定句式、连续表达或品牌口吻；语言动作仅用于组织证据。
- 准确性提醒集中出现一次即可；禁止为了显得严谨反复使用“边界、并非、尚未、不能据此”等审稿式句型。
- 全文使用 4–6 个自然小节；每节承接上一节留下的问题，去掉小标题后仍能连续读通。
- 最后一行必须是 `状态：等待用户确认`。
